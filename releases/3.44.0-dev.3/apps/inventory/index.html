Outils

Choisir, créer ou importer un inventaire

Chaque navigateur possède sa copie locale. Pour travailler sur plusieurs postes, exportez le même inventaire de départ, travaillez séparément, puis réimportez les fichiers sur le poste principal : les scans sont fusionnés par code-barres.

Principe : l’inventaire et les scans sont stockés dans IndexedDB sur ce poste. Les données Koha ne servent pas de stockage d’inventaire. Les écritures Koha sont toujours des actions explicites : corrections validées, retours, désherbage ou statuts appliqués aux non-passés.

Synchronisation multi-postes

L’export JSON contient l’UUID de l’inventaire, les scans, les conflits et les suppressions/annulations synchronisées. Même code-barres + même zone = fusion automatique. Même code-barres + zones différentes = conflit à arbitrer. Une suppression explicite reste supprimée sur les autres postes au lieu d’être recréée par la fusion.

Qualité du catalogue et rapport final

Agrégation locale des scans fusionnés, selon les colonnes d’erreurs définies dans le snapshot de configuration de cet inventaire.

4 · Colonnes du tableau d’erreurs / correspondance des champs

Ces correspondances pilotent aussi les champs Public, Type, Sous-localisation, Étage et Statut dans les zones. « Public » est distinct de CCode et lit par défaut la notice MARC 999$q. « Étage » est distinct de la numérotation générique : il lit items.enumchron et traduit sa valeur avec la catégorie de valeurs autorisées ETAGE.

5 · Statuts et actions automatiques

Mode sûr Koha 25.11 : les corrections automatiques au simple scan sont neutralisées. Les écarts sont détectés puis corrigés explicitement avec le bouton Corriger. Le désherbage automatique reste uniquement disponible dans le mode rapide, avec confirmation d’activation pour la session.
